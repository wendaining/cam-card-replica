# ADR-0003：用 Codable + 文件持久化，不用 SwiftData

- 状态：接受
- 日期：2026-10-27

## 背景

需要"杀进程重启数据还在"，且数据量很小（几十张名片）。

## 决策

`CardStore` 协议 + `FileCardStore`：`library.json`（原子写）+ `Images/<uuid>.jpg`。

> 这两个是**运行时产物**，不在仓库里；仓库里只有读写它们的代码和测试。运行时位置：`~/Library/Application Support/CamCardReplica/`（模拟器里在对应 App 容器内）。

## 理由

1. **可检查**：JSON 能直接看，评测脚本、答辩演示都能当场打开。
2. **可测试**：T18 只需对比"重新构造 model 后能否读到"，无需模拟器。
3. **无迁移负担**：SwiftData 的 schema 迁移在作业周期内是纯风险。
4. **图片与记录解耦**：删除名片能精确删文件，不会留下孤儿 BLOB。

## 代价

- 无查询引擎/关系：搜索是内存过滤，几千条以内无问题。
- 需要自己保证原子性与并发（已用临时文件 + replaceItem）。

## 后果

- 若将来数据量增长，替换 `CardStore` 实现即可，上层不动。

## 2026-10-28 可靠性补充

仓库先保存候选 JSON，再发布内存；新增两图写入或 JSON 提交失败清理本次图片，删除先提交 JSON 再清理无引用图片。损坏库加载失败时禁止用空库覆盖。图片与 JSON 不是跨文件事务：进程在清理窗口终止可能残留孤儿图片，但已提交记录不会因提前删图而丢失图片。

重建模型只验证文件回读。T18 另用独立 UUID 子库真正 terminate/launch，核对修改、标签、备注和两张图；真机上划杀进程仍待手工签收。
