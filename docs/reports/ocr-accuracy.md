# OCR 与字段抽取准确率（2026-10-28）

语料 v2：50张合成名片/76张图，业务 GT 不变，字体按编号轮换，图片与 v1 不同。环境：Xcode 27.1 / iPhone 18 Pro / iOS 27.0。命令：make bench；python3 Scripts/report_benchmark.py。原始数据与全部切片见 [图像完整测量](image-accuracy-latest.md) 和对应 JSON。

## 三种数字不能混用

| 测量 | 输入与比较 | 用途 |
|---|---|---|
| 历史首值门槛 | GT 拼成理想文本；首个邮箱/每类首个号码 | 保留既有回归门槛，不表示多值完整或 OCR 正确 |
| 理想文本完整集合 | 全号码/邮箱/可选字段，比较完整集合与全部缺失项 | 揭露漏值、多值和无标签归类歧义 |
| 图像完整字段 | 全部76张图真实检测/校正/Vision/解析，再逐字段对 GT | 评估真实图像链路；按语言、字体、版式、标签、图像种类切片 |

## 理想文本首值历史结果

| 字段 | 正确/总数 | 门槛（未下调） |
|---|---:|---:|
| name/company/jobTitle/email/website/address | 各50/50 | 原字段门槛保留 |
| phone_mobile | 50/50 | ≥98% |
| phone_office | 49/50 | ≥95% |
| phone_fax | 45/50 | ≥85% |
| missing_website_legacy | 15/15 | 缺网站不得误填 |

原 no_hallucination 名称已更正为 missing_website_legacy。它只有15次缺网站检查，不能推出所有字段幻觉率为零。

九个 fixture 的 OCR 冒烟检查另有 expected-line recall：每张图按完整 present_text 行是否出现在 OCR 中计数，再对图片取平均，门槛仍为大于0.7。它是整行命中比例，不是字符召回率，也不替代全部图片的完整字段测量。

这张表把漏掉/多出的第二个值算错。无标签传真无法可靠区别于座机或手机：既定格式推断存在误归类，不能把号码“确实在卡上”说成类型也正确。完整统计照常计错，单测用明确的期望失败标出已知歧义；有标签号码和非电话缺失字段继续严格断言。没有用 GT 或号码顺序硬编码 office/fax。

## 真实图像结果与错误

完整明细在 [image-accuracy-latest](image-accuracy-latest.md)，含每图期望值/实际值；所有图片均执行并产出文字，统计包含缺失、错误和额外值。比较忽略大小写/首尾空白，保留电话内部格式；空串与 nil 均表示缺失。

主要错误仍包括 Vision 的 0/O/l/1 混淆、中文近形字、地址漏字/空格与部门归类。不能把理想文本的100%描述为图像 OCR 100%。v2 更换字体后，不与 v1 的9个 fixture 或审查额外测量直接作差。

新字体曾让 @ 被读错，裸域名因此被当成网站。已用通用证据规则回归：网站需要 www/http(s) 前缀或网站标签；裸域名留在未归类文字供人工确认。代价是无标签、无前缀的真实网址需要人工补入，优先遵循不虚构字段。

已知限制：无标签国际号码/座机/传真歧义、竖排文字、艺术字、强反光、多名片同框。照片与遮挡仅为合成分布，不能代表真实拍照质量。
