# 演示脚本与答辩准备

> 目标：**90 秒**讲完整个闭环，每一步都落到一条验收测试上；再准备 3 分钟版
> 应对"你再多讲点"的场面。
> 前提：模拟器已装好，App 已 build（`make build`），并提前 5 分钟打开过一次。

---

## 0. 演示前 3 分钟检查

```bash
xcrun simctl boot "iPhone 18 Pro"     # 启动模拟器
make build                             # 确认能编译
open CamCardReplica.xcodeproj          # Cmd+R 先跑一遍，确认启动到名片夹
```

- **关掉网络**（证明全离线）：飞行模式 / 拔网线。系统设置里断网即可。
- 把「测试名片」按钮的位置记住（扫描页右下角，试管图标）。
- 备用：如果现场模拟器抽风，直接播提前录好的 30 秒录屏（`/tmp/camcard-shots` 截图可当静态版）。

## 2. 必须主动说出口的三句话

这三句是评分点，别等老师问：

1. **"我们的确定性验收是 20 条场景，其中 15 条有自动化 UI 测试，剩下的
   （真实相册选择、真机杀进程、真机通讯录）需要手工，清单在 `docs/testing/test-plan.md`。"**
2. **"OCR 是概率性功能，我们没有追求逐字一致，而是做了量化评测：50 张语料、
   8 个字段、按语言和有无标签切分；幻觉率必须是 0。"**
3. **"我们发现并且修掉了一个真实 bug：透视校正的坐标系反了（左上 vs 左下），
   斜拍名片校正后上下翻转、OCR 出乱码。修完之后斜拍样本从完全不可用变成姓名公司全对。"**

## 3. 3 分钟版：加讲的四段

### 3.1 为什么不用 SwiftData / 云 OCR / 大模型

- 数据量几十条，JSON 可直接打开、可 diff、删除名片能精确删图片；SwiftData 的
  迁移在两周作业里是纯风险。
- 云 OCR：结果随模型更新漂移，评测数字不可复现，演示还怕断网。
- 大模型抽字段：会有"合理猜测"，而作业第八节明确说**猜测就是错误**。

### 3.2 准确率怎么看

打开 `docs/reports/ocr-accuracy.md` 第二之三节：

- 有标签的名片：**八个字段 100%**；
- 无标签的名片：fax 只有 61.5%，因为 `+44 20 0000 7001` 这种串没有标签时
  根本不含"是传真"的信息；
- 我们的选择是**不猜**：归为 mobile、置信度降到 0.62、UI 标「请确认」。

一句话总结：**"能到 100% 的地方我们做到了 100%，做不到的地方我们明确标出来，而不是编一个。"**

### 3.3 可测试性怎么来的

`AppServices.make(arguments:)` 是唯一装配点。启动参数 `-ui-testing`、
`-fixture-camera`、`-camera-permission denied`、`-fixture-name zh-01`
让它切到内存存储 / 固定图片 / 固定权限。生产代码里没有 `if debug`。

### 3.4 SDD 怎么落地的

- 规格编号（`7.5.3`）→ `docs/spec/acceptance.md` 的追溯表 → 测试方法名 → 代码文件；
- 语料是脚本生成的，seed 固定，谁跑都是同一批图；
- 每个提交都是 Conventional Commits，改解析规则必须带测试。

## 4. 可能被追问的问题

| 问题 | 回答要点 |
|---|---|
| 为什么不用第三方 OCR？ | 见 3.1；核心是确定性与可复现性，另外作业不要求复现其专有算法 |
| OCR 准确率多少？ | 分两层：文字召回（6 张 fixture，平均 0.89）；字段准确率（50 张，见报告）。**不要只报一个数** |
| 怎么保证不瞎编字段？ | 置信度阈值 0.5，低于就 `nil`；每个值带 evidence；语料里 15 张标了 `expected_absent`，专门测幻觉率，结果 0% |
| 数据怎么存的？ | `Application Support/CamCardReplica/library.json` + `Images/<uuid>.jpg`；原子写；删除名片同时删图 |
| 多电话怎么区分？ | 标签优先 → 号码格式（1[3-9]、0 开头、400/800）→ 兜底低置信；同类可多个 |
| 杀进程真的还在？ | 现场演示；单元测试 `testPersistenceRoundTripThroughFileStore` 也覆盖 |
| 模拟器没摄像头，你怎么测拍照？ | 协议注入 fixture；真机路径是 `AVCaptureSession`，没改过 |
| 你和 CamCard 差多少？ | 诚实回答：功能闭环对齐，UI 未逐像素对齐，差异清单在 `docs/reports/difference-analysis.md`（待补参考截图） |
| 哪些地方你认为做得不够？ | 竖排文字、强反光、一张图多张名片；这是下一阶段要做的 |

## 5. 演示失败时的兜底

1. 网络已断但仍失败 → 重启 App（`xcrun simctl terminate` + 重开），数据在磁盘上不会丢。
2. 模拟器起不来 → 用 `docs/reports/screenshots/` 里的 5 张截图讲完整流程。
3. 时间被压缩到 30 秒 → 只做：空态 → 扫描 → 确认页（讲"AI 输出≠数据"）→ 保存 → 列表现身。
