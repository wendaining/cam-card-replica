# CamCard 官方资料调研与功能对比

> 查阅日期：2026-10-30。依据是公开官网和官方帮助页；本轮未操作正版 App。人工验收按当前安排暂缓。

## 调研记录

这次先看了官网首页，再看 iPhone 平台的帮助页。首页主要介绍数字名片和企业服务，和本次作业直接相关的是“名片扫描识别，在线管理商业人脉”。帮助页更具体：识别后会进入信息校对界面，已经保存的名片也能从名片夹进入编辑，并选择存入手机通讯录。这说明名片扫描只是入口，识别后的核对和后续管理同样是产品流程的一部分。

另一点是识别质量。帮助页专门提到光照和语言设置，说明不能把一次拍照的识别结果当成可靠的最终数据。因此本项目保留识别原文和结构化结果，让用户修改后再保存；评测时分别记录 OCR 错字与字段归类错误，不把两者混成一个问题。

帮助页还介绍了长按拖拽分组。本项目采用标签选择和筛选，管理目的接近，但交互方式存在差别。这里保留这个差异，不写成逐步操作完全一致。帮助页中仍能看到 iOS 6 的说明，所以它能支撑历史功能调研，不能代替当前指定版本的操作记录。

## 功能与差异

| 项目 | 官方资料说明 | 本项目行为及证据 | 对比结论 |
|---|---|---|---|
| 扫描识别 | S01 提供名片扫描识别 | Vision OCR、原图与校正图；VisionOCRTests、CardDetectorTests | 功能方向一致；没有测量正版同图结果 |
| 识别后校对 | S02 明确识别后出现校对界面 | ReviewView 编辑后确认保存；T11/T12 | 核对后保存的主线有资料支持；界面布局未比较 |
| 已保存记录编辑 | S02 从名片夹选择名片并编辑 | 列表进入详情、编辑、保存；T13/T14 | 有相应能力，入口层级未确认一致 |
| 通讯录 | S02 可在校对/编辑时选择保存到手机通讯录 | 详情显式导出；ContactsExporterTests、VCardDocumentTests | 入口不同；课程允许通讯录或 VCF 二选一，当前按自动测试交付 |
| 分组管理 | S02 介绍编辑状态下拖拽分组 | 标签选择、附加和筛选；T16 | 管理目的接近，分组与标签不能直接认定语义或交互等价 |
| 识别失败 | S02 提到光照、语言设置和反馈图片 | 错误提示、重拍、空结果手填；ScanFlowModelTests、T20 | 本项目恢复路径已测；正版错误页面和恢复状态未实测 |
| 数据保留 | S02 介绍账号云同步与备份 | 本地 JSON/图片，重启回读；T18 | 本地持久化覆盖课程范围；不具备云备份或重装恢复 |
| 企业和数字名片 | S01 展示企业服务、数字名片分享等 | 按课程范围不实现 | 属于明确排除的功能，不作为核心缺陷 |
| 检测与方向校正 | S02 拍摄建议提及自动识别文字方向，未说明边界算法 | 自动四角、手动调整、透视与 EXIF 方向处理 | 只能证明本地规格覆盖，不能证明和正版采用同样的方向策略 |

## 可观察等价性的论证范围

本项目以课程规定的名片数字化和联系人管理切片为范围，把可见行为拆成六个维度，再用参考用例关联本地证据。判断等价时比较用户动作及其可见结果，不要求采用相同内部算法。

| 维度 | 本地可检验的契约 | 证据 | 目前能得出的结论 |
|---|---|---|---|
| UI | 列表、扫描、校对、详情及空态可达，字段可见 | T01/T02/T07/T13，ScreenshotTests | 页面能力已有；缺少正版基线，不能证明视觉等价 |
| 交互 | 修改、保存、搜索、标签和删除产生预期结果 | T11–T17 | 本地操作契约已测；官方资料支持编辑和管理目的，不覆盖全部操作细节 |
| 状态 | 保存后更新列表，取消不新增，失败保留可重试状态 | T12/T20，ScanFlowModelTests | 本地状态转移有回归保护；正版同条件状态待观察 |
| 数据 | 保留图片、字段和人工修改，重启后可读，导出正确映射 | T18/T19，RecognitionSnapshotTests | 本地数据契约已有测试；未做正版同输入逐字段对照 |
| 异常 | 权限拒绝禁用拍摄，空结果可手填，写失败不丢表单 | T03/T20，CameraPermissionTests | 注入异常可验证；不推断正版提示文案及系统弹窗一致 |
| 工作流 | 导入/拍摄到核对保存，再打开、管理和导出 | T04–T19，官方 S02 | 核心工作流与官方描述相符；尚非指定版本端到端等价证明 |

本轮可以支持的结论是：本项目覆盖课程核心功能，主流程与官方公开说明相符，并有本地自动化证据。官网资料不足以证明当前正版在 UI、交互细节和所有异常条件下完全等价；这部分保留未确认，不补写未经执行的通过记录。

## Reference Test Suite 与观察记录的关系

两者不是同一份材料。观察记录回答“参考产品有什么行为，依据是什么”；Reference Test Suite 回答“给定条件下怎样操作，什么结果算通过”。课程第十七节已给出 T01–T20，可直接作为用例来源，不需要假称它们来自本轮官网观察。

[课程原始参考用例整理](../testing/reference-test-suite.md) 保留课程语义；[本地测试计划](../testing/test-plan.md) 写执行步骤和替代路径；[验收追溯矩阵](../spec/acceptance.md) 连接测试与实现。官网支持的部分标明 S01/S02，未公开的行为仍以课程规格为预期。
