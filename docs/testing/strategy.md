# 测试策略

## 三层

| 层 | 位置 | 跑得多快 | 覆盖什么 |
|---|---|---|---|
| 单元 | `Tests/Unit` | 秒级 | 解析规则、电话分类、文本归一化、仓库、vCard |
| 集成/评测 | `Tests/Integration` | 秒~分钟 | 50 张语料的字段准确率、幻觉率 |
| 端到端 | `UITests` | 分钟 | T01–T20 的真实交互路径 |

## 为什么这么分层

- 解析器是纯函数 → 语料评测可以做得很便宜，改一条规则跑一遍就知道回归面。
- UI 测试慢且脆 → 只覆盖"用户能看见的行为"，不在 UI 测试里断言正则细节。
- 没有摄像头 → 用 fixture 注入，让端到端测试在模拟器上也能跑（ADR-0004）。

## 语料（TestData/）

- 50 张合成名片，共 **76 张图**：
  - 50 张干净渲染（`flat`，OCR/解析的评测主体）；
  - 12 张"照片变体"（`photo`：透视、阴影、杂乱背景、轻微模糊）；
  - **10 张边缘遮挡**（`occluded`：手指压住一角，只为打断轮廓，不遮文字）；
  - **4 张照片 + 遮挡**（`occluded-photo`：桌上名片 + 手指压角，专测边界检测）。
- 语言：中文 15 / 英文 15 / 中英双语 20。
- 版式：左对齐、居中、两栏、竖版、极简；深浅主题；有无 Logo；有无标签行。
- Ground Truth 字段：8 个业务字段 + `expected_absent`（**用于幻觉率**）+ `present_text`（用于 OCR 召回）。
- 生成：`python3 Scripts/generate_test_cards.py --clean`，seed=20261027。
- **可复现性**：脚本曾用 Python 的 `hash()` 做纸纹种子，而 `hash()` 每个进程都加盐，
  导致每次重跑所有 PNG 都变。已改为 `sha256(card id)`，连续两次 `--clean` 的
  `shasum` 完全一致（72→76 个文件逐一比对过）。

## 判定标准

- **确定性 20 条**：全绿为通过，任何一条红都不算完成。
- **字段抽取**：按字段统计准确率，阈值写在 `ParserBenchmarkTests`；
  照片变体单独统计，不参与阈值（真实拍摄质量不在可控范围）。
- **幻觉率**：`expected_absent` 中出现却被填上的比例，必须为 0。

## 已知不可自动化项

| 项 | 原因 | 替代手段 |
|---|---|---|
| 真实相机拍摄 | 模拟器无摄像头 | fixture 注入 + 真机手工验收（附截图） |
| 系统权限弹窗 | XCUITest 对系统弹窗不稳定 | 协议注入两条分支 + 真机手工验收 |
| 杀进程重启 | UI 测试无法真正 kill | 单元测试重建 store 模拟 + 真机手工验收 |
| 与正版 UI 逐像素对比 | 无真机/正版截图 | 提供并排截图对比清单，人工确认 |

## 运行

```bash
make test        # 单元 + 集成（57 个）
make test-ui     # T01–T20（15 个用例，约 2.5 分钟）
make test-ipad   # 同一套在 iPad 上跑，验证布局
make bench       # 只跑语料评测并输出表格
```

| 设备 | 系统 | 结果 |
|---|---|---|
| iPhone 18 Pro | iOS 27.0 | 60 + 16 全绿 |
| iPad Pro 11-inch (M5) | iOS 27.0 | 15/15 全绿（布局适配已验证） |
